## Design (you may improve; keep every point)
HOVER (cards that have an entry get a class from JS, e.g. `shop-card-pop`): on hover AND keyboard focus: the card grows a little but clearly (about scale 1.06 to 1.08) and lifts (translateY about -4px), the shadow gets bigger, the border/outline gets the site's warm colour, the picture (`.shop-bubble`) pops a little (scale about 1.12, a small tilt), `cursor:pointer`; pressed = a small squeeze. Smooth (about 160-220 ms), sits ABOVE its neighbours (z-index) and is never cut by a column or group edge (check `overflow` of `.shop-groups`/`.shop-group`; columns + `break-inside:avoid`), text stays sharp and readable, no layout shift (transform only). `prefers-reduced-motion: reduce` (and the site's own calm setting, if it has one: read css/styles.css and js/main.js) = no scale and no tilt, only the shadow/outline change. Guard the grow with `@media (hover:hover)` so a tap on a phone does not leave a card "stuck" big (the focus/active style still shows). Hover must not make any test measure overlap at rest.
POP-UP: made by JS on the first open: ONE `div.shop-pop` (overlay) with `div.shop-pop-box` (`role="dialog" aria-modal="true" aria-labelledby=<title id>`). `<dialog>` and `:has()` are banned by the repo's rules (tests/code-rules): use div + role. Centred in the window (horizontally and vertically; `max-height: 85vh`, scroll inside the box if it is taller; width `min(92vw, 34rem)`), dim backdrop, a close button (X, 44 px target, named "Close" in each language) and a "Close" text button at the bottom, closes on Esc, on a click on the backdrop and on the close buttons; opens/closes with a short fade+scale (about 160 ms; none with reduced motion); the page behind does not scroll (lock without the page jumping sideways: compensate the scrollbar width) and is hidden from screen readers while open (use `aria-hidden` on the other top-level blocks, or `inert` ONLY if the browser-support table allows it: list any new names you need); focus moves into the box on open (the close button or the box), Tab/Shift+Tab stay inside, and focus goes BACK to the card that opened it. Content, top to bottom: the product picture (clone of the card's `<svg><use>`, big), the name (as the card shows it, translated) and price, the card's own note if any, the BIG disclaimer box (decision 3), the heading "Ingredients" (or "Made of" for things that are not eaten/used on skin; the data says which), the list as neat chips or a tidy list (make it look good: the site's colours, rounded, easy to scan), the optional "Contains:" line in bold, a small line "Sample list" is NOT needed (the disclaimer covers it). Use the site's fonts and tokens (read css/styles.css); contrast >= WCAG AA (the repo has contrast-pixels).
OPENING: click, Enter and Space on the card. For keyboard and screen readers each interactive card must have a real control. `<li>` must stay `<li>` (axe "list" rule); do not put `role=button` on the `<li>`. Recommended: JS adds one `<button type="button" class="shop-open">` inside the card (visually hidden text OR a transparent stretched button covering the card with `::after`/absolute), accessible name = the product's name + the translated words "ingredients" (e.g. "Hot pretzel, $5, show ingredients"); re-label it when the language changes (js/i18n.js re-writes `data-t` text on a language change: do NOT put the button inside an element that i18n re-writes). One Tab stop per card is accepted. Touch: whole card is the target. Do not use `title`.
LOADING: first-visit weight must not grow for people who never touch a card, and in the REAL site file set (no tour, no demo, no js/shop-sample.js) the extra bytes must be tiny. Suggested: the hover CSS is a short block at the end of the Store rules in css/extras.css; the pop-up CSS is `css/shop-pop.css`, loaded lazily (copy how js/tour.js loads css/tour.css, including the "inline" case: the preview inlines CSS as `<style data-...>` and scripts: support `style[data-shop-pop-css]` and an already-present `window.WA.shopSample`... name it like the tour does); `js/shop-pop.js` is the loader + the pop-up code; it is added to index.html as ONE `<script>` tag only if the slow-phone budget (<= 24 files) still holds in the REAL file set, otherwise fold the tiny loader into an existing file. Measure with `node tests/slow-phone.test.mjs` on a copy of the page set WITHOUT tour/demo/sample (main did this check before: real tip = 404 KB; the integ clone has the tour in it and is over 420 KB on purpose: the tour is preview-only), and report file counts and encoded bytes before/after.
